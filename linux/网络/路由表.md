路由表的作用就是决定：一个数据包要去某个目标 IP，应该从哪里出去、经过哪个网关。

它就像一个城市的交通导航系统，告诉数据包应该走哪条路。

我们结合云服务器中的 VPC、子网、EIP、NAT 来理解。

## 一、先理解一个生活中的例子

假设你住在一个小区里：

- 小区：VPC
    
- 小区里的不同楼栋：子网（Subnet）
    
- 小区出口：网关（Gateway）
    
- 交通路线规划：路由表（Route Table）
    

现在你想去三个地方：

1. 去小区里面另一栋楼。
    
2. 去附近的商场。
    
3. 去国外的网站。
    

这三个目的地可能需要走不同的出口。

网络也是一样的。

当一台云服务器要访问某个 IP 时，系统需要判断：

- 目标 IP 属于哪个网段？
    
- 应该直接在内部网络通信吗？
    
- 应该经过 NAT 网关吗？
    
- 应该通过 Internet 网关访问公网吗？
    

这些判断就涉及路由表。

## 二、路由表里面有什么？

路由表最核心的就是两部分：

1. 目标网段（Destination）
    
2. 下一跳（Next Hop）
    

举个例子：

假设你的 VPC 网段是：

`10.0.0.0/16`

你的路由表可能长这样：

|目标网段|下一跳|
|---|---|
|10.0.0.0/16|Local|
|192.168.0.0/16|Peering|
|0.0.0.0/0|NAT Gateway|

我们逐条解释。

第一条：10.0.0.0/16 → Local

意思是：

如果目标 IP 在 `10.0.0.0/16` 这个网段里面，就走 VPC 内部网络。

例如：

你的服务器 A：

`10.0.1.10`

服务器 B：

`10.0.2.20`

A 想访问 B。

因为 B 属于 `10.0.0.0/16`，所以直接通过 VPC 内部网络通信，不需要经过公网。

第二条：192.168.0.0/16 → Peering

意思是：

如果目标 IP 属于 `192.168.0.0/16`，就通过 VPC 对等连接访问另一个 VPC。

例如：

- VPC A：10.0.0.0/16
    
- VPC B：192.168.0.0/16
    

两个 VPC 通过 Peering 连接。

那么 A 访问 B，就需要通过对等连接。

第三条：0.0.0.0/0 → NAT Gateway

这条非常重要。

`0.0.0.0/0` 代表所有 IPv4 地址。

意思是：

如果目标 IP 没有匹配到更具体的路由规则，就把数据包交给 NAT 网关处理。

例如：

服务器访问：

`8.8.8.8`

它不属于前面两个网段，于是匹配默认路由，交给 NAT 网关。

最终通过 NAT 网关访问公网。

## 四、路由表有一个非常重要的规则：最长前缀匹配

这个是理解路由表必须掌握的知识。

假设路由表有三条规则：

|目标网段|下一跳|
|---|---|
|10.0.0.0/8|网关 A|
|10.0.1.0/24|网关 B|
|0.0.0.0/0|网关 C|

现在服务器要访问：

`10.0.1.100`

它同时匹配：

- 10.0.0.0/8
    
- 10.0.1.0/24
    
- 0.0.0.0/0
    

那到底走哪个？

答案是：网关 B。

因为 `/24` 比 `/8` 更具体。

这叫最长前缀匹配（Longest Prefix Match）。

简单理解：

路由表中有多条规则匹配时，优先选择目标范围最小、最具体的那条规则。

## 五、路由表和安全组有什么区别？

这个地方特别容易混淆。

|对比|路由表|安全组|
|---|---|---|
|核心作用|决定数据包往哪里走|决定数据包能不能通过|
|关注点|下一跳、目标网段|端口、协议、IP|
|典型配置|0.0.0.0/0 → NAT|允许 TCP 443|
|类比|导航系统|门卫、安检|

举个例子：

你的 Java 服务部署在云服务器上，监听 8080 端口。

另外一台机器想访问它：

1. 路由表：有没有通往目标服务器的网络路径？
    
2. 安全组：是否允许对方访问 TCP 8080？
    
3. 服务器防火墙：是否允许 8080？
    
4. Java 应用：是否真的监听 8080？
    

这几个环节都可能影响连接是否成功。

## 六、你在云平台上配置路由表时，应该关注什么？

实际工作中经常会看到这些配置：

|目标网段|下一跳|用途|
|---|---|---|
|VPC 网段|Local|VPC 内部通信|
|0.0.0.0/0|NAT Gateway|通过 NAT 访问公网|
|0.0.0.0/0|Internet Gateway|通过互联网网关访问公网|
|其他 VPC 网段|Peering|跨 VPC 通信|
|指定网段|VPN Gateway|访问企业内网|

注意：具体下一跳类型和配置方式会因云厂商而异。

## 七、最后给你一个实际开发场景

假设你们公司有一个达人数据分析系统：

- Java 后端服务器：10.0.1.10
    
- MySQL：10.0.2.10
    
- Redis：10.0.3.10
    
- Elasticsearch：10.0.4.10
    

现在：

1. Java 需要访问 MySQL。
    
2. Java 需要访问 Redis。
    
3. Java 需要访问 Elasticsearch。
    
4. Java 需要访问第三方视频平台 API。
    

你就可以理解：

- 访问 MySQL、Redis、ES：通常通过 VPC 内部路由。
    
- 访问第三方视频平台：需要通过 NAT 或其他公网出口。
    
- 路由表负责决定这些数据包应该走哪个网络出口。

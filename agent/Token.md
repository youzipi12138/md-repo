# **一、先理解 Token：大模型处理文字的基本单位**

## **1. Token 到底是什么？**

我们平时使用文字时，最小的理解单位通常是：

- 中文：汉字
    
- 英文：单词
    
- 程序：字符、变量、函数
    

但是，大语言模型并不是直接按照汉字、单词来处理文本的。

它处理的是 Token。

**Token 是模型处理文本时使用的基本编码单位。**

例如：

**原始文本**

`我想找一些适合投放 AI 产品的抖音达人`

**Token 化后的示意**

我

想

找

一些

适合

投放

AI

产品

的

抖音

达人

仅为示意，真实 Token 切分取决于模型使用的 Tokenizer，不一定一个词对应一个 Token。

注意：Token 不等于字数，也不等于单词数。

比如：

|内容|Token 数量特点|
|---|---|
|一个英文字母|可能不足 1 个 Token，也可能与其他字符组合|
|一个常见英文单词|可能是 1 个 Token|
|一个生僻英文单词|可能拆成多个 Token|
|一个常见汉字|可能是 1 个或多个 Token|
|一段 JSON|取决于字段名、符号和值|
|一段代码|可能包含大量 Token|

所以，不能简单地认为：

- 1000 个汉字 = 1000 Token
    
- 1000 个英文单词 = 1000 Token
    

它们不是一回事。

## **2. Token 是如何产生的？**

这里要引入一个概念：Tokenizer（分词器）。

Tokenizer 的作用就是：

**把人类输入的文本转换成模型能够处理的 Token ID 序列。**

大致过程如下：

**用户输入**

`帮我推荐适合 AI 产品的达人`

**Tokenizer**

文本切分、编码

**Token ID**

`[..., ..., ..., ...]`

**模型**

根据 Token 序列进行计算和预测

这里有两个非常重要的概念：

**第一，Token 和 Token ID 不一样。**

- Token：分词后的文本片段。
    
- Token ID：这个文本片段在词表中的数字编号。
    

例如，假设 Tokenizer 有一个词表：

|Token|Token ID|
|---|---|
|hello|15339|
|world|1917|
|AI|12345|

这里只是举例，真实 ID 取决于具体 Tokenizer。

**第二，不同模型的 Tokenizer 可能不同。**

同样一句话：

- GPT 系列模型可能切分成一组 Token。
    
- Claude 可能切分成另一组 Token。
    
- Qwen 可能切分成另一组 Token。
    

所以，同样一段文本，在不同模型上消耗的 Token 数量可能不同。

## **3. 为什么模型要使用 Token，而不是直接使用汉字？**

因为模型本质上需要把文本转换为数字，才能进行矩阵计算。

如果直接使用字符，会有一些问题：

1. 词汇表达能力有限。
    
2. 需要处理大量字符组合。
    
3. 很难高效表示常见词语和语言结构。
    

Token 化可以在字符、词语和子词之间取得平衡。

例如：

- `recommendation` 可能被作为一个 Token，也可能拆分。
    
- `recommend` 和 `ation` 可能分别出现。
    
- 常见的中文词语也可能被合并编码。
    

这就是 Tokenizer 的核心价值。
